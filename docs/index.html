Pilot communities in Bukit Batok

How BlockBuddy works

The website is still a static site on GitHub Pages. Supabase holds the accounts, the database, private documents and live chat. The browser uses the publishable key. There is no service-role key in this project.

Sign-in

People create an account with email and password. Supabase emails a confirmation link, and a separate link for a forgotten password. Those links must be allowed to return to https://ianjameslaird-gif.github.io/blockbuddy/. The free Supabase mailer only sends a small number of messages an hour. Custom SMTP is the right setup before a wider launch.

Residence check

A member covers account numbers on a photo. The browser burns those boxes into a JPEG and uploads only that image. PDFs are turned away so the original file never has to leave the device. The file sits in a private bucket at verification-docs/<user id>/…. The member can read their own file. Admins can read all of them. Nobody else can.

A reviewer approves it, marks it under review, or sends it back as Action Needed with a note. The member cannot change that status themselves. The file is deleted 90 days after a decision. Under review is not a decision, so that file stays until someone approves it or asks for another photo.

The marketplace

Listings, search and filters run in Postgres and are limited to verified members of the same community. Photos live in a second private bucket. Chat is a private thread between two people, delivered with Supabase Realtime. Blocking hides listings and messages in both directions. Reports go to the reviewer queue. Unit numbers such as #12-345 are rejected in the browser and again in the database. Profiles never store a unit number.

Tables

  • communities — SkyPeak @ Bukit Batok (skypeak-bukit-batok), Golden Daisy, Skyline II @ Bukit Batok, Skyline I @ Bukit Batok, Sky Vista @ Bukit Batok and West Terra @ Bukit Batok. Sign-up sends community_slug.
  • profiles — display name, bio, community, verification status.
  • profile_private — admin flag and the note the member sees. Neighbours cannot read this table.
  • verification_submissions — each document, the decision and when the file was deleted.
  • listings — sell, wanted, give away, trade.
  • blocks, conversations, messages, conversation_reads — privacy between two neighbours.
  • reports and audit_log — the reviewer queue and who did what.

Who can see what

Row level security is on for every public table. Anonymous visitors can read community names, slugs and resident labels, and nothing else. Verified neighbours see their own community’s active listings and each other’s public profiles. They do not see documents, admin flags, other people’s chats, or someone they have blocked. Admins use the same signed-in role, and the admin flag is global across communities. Extra access goes through checks such as private.is_admin(), which reads the admin flag without getting stuck in a policy loop. The private schema must stay off the Data API list.
