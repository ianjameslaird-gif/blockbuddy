For a real launch

What GitHub Pages cannot host

This prototype is a static site. Accounts, listings, chats and document previews stay in the browser. A public launch of BlockBuddy needs a backend. GitHub Pages can only serve files like these.

Pages is not a server

GitHub Pages cannot sign people in, store private documents, run a database, deliver chat, or hold a moderation queue.

Authentication

Real accounts need sign-up, sign-in, password reset and sessions that expire. Passwords must be hashed. A later Singapore step could add Singpass or MyInfo so residence is checked without relying only on uploaded letters.

Private document storage, with retention

Proof of residence belongs in a private bucket, encrypted, and visible only to authorised reviewers. Neighbours never receive a link. Suggested rule: delete each file 90 days after a decision, whether the member was approved or the case was closed. Redaction should happen before the file is stored. The prototype never uploads a file.

A database

Communities, members, verification status, listings, reports and blocks need a database. Each feed is a query for one verified community, not a public folder. Unit numbers stay in the review record and are stripped from profiles, listings and chat.

Realtime chat

Private threads need a websocket or a similar service, with block rules enforced on the server. Messages in this prototype are saved only on the device.

Moderation

Reviewers need a queue for residence documents and for member reports, plus an audit log of who opened a document and when the decision was made. Reports in the prototype are stored locally so the flow can be tried. Nobody else can see them.
